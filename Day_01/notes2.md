# What is a Dependency?

A dependency is a package or library that your project needs in order to work.

Example:

```bash
npm install express
```

This installs the Express package and adds it as a dependency.

Without dependencies, we would have to write everything from scratch.

---

# package.json

## Definition

`package.json` is the main configuration file of a Node.js project.

It acts as the **blueprint** of the project and tells npm:

* Which packages are needed
* Which versions are acceptable
* How to run the project
* Project metadata

---

## Example

```json
{
  "name": "my-app",
  "version": "1.0.0",
  "dependencies": {
    "express": "^5.1.0",
    "mongoose": "^8.0.0"
  },
  "scripts": {
    "start": "node server.js"
  }
}
```

---

## Information Stored in package.json

### Project Metadata

```json
{
  "name": "my-app",
  "version": "1.0.0"
}
```

Contains project information.

### Dependencies

```json
{
  "dependencies": {
    "express": "^5.1.0"
  }
}
```

Lists packages required by the project.

### Scripts

```json
{
  "scripts": {
    "start": "node server.js",
    "test": "jest"
  }
}
```

Run scripts using:

```bash
npm start
npm test
```

---

## Purpose of package.json

Imagine you build an application and upload it to GitHub.

Without `package.json`, other developers would not know:

* Which packages to install
* Which versions to use
* How to run the project

With `package.json`, they simply run:

```bash
npm install
```

and npm installs all required dependencies automatically.

# package-lock.json

## Definition

`package-lock.json` is automatically generated by npm.

It records the **exact versions** of every installed package and dependency.

---

## Example

Suppose package.json contains:

```json
{
  "dependencies": {
    "express": "^5.1.0"
  }
}
```

npm may install:

```text
express@5.2.0
```

The lock file records:

```json
{
  "packages": {
    "node_modules/express": {
      "version": "5.2.0"
    }
  }
}
```

---

## Why package-lock.json Exists

> 💡 Without a lock file, different developers may install different versions of the same package, causing inconsistent behavior.

Example:

Developer A installs:

```text
express@5.1.0
```

Developer B installs:

```text
express@5.2.0
```

Different versions can lead to bugs that only appear on some machines.

With a lock file, everyone installs the exact same versions.

---

## What package-lock.json Stores

### Exact Package Versions

```text
express@5.2.0
```

### Full Dependency Tree

Example:

```text
express
├── body-parser
├── cookie
├── debug
└── mime-types
```

The lock file stores every dependency and sub-dependency.

---

## Purpose of package-lock.json

Provides:

* Reproducible builds
* Consistent installations
* Same environment for all developers
* Fewer "works on my machine" issues

---

# package.json vs package-lock.json

| Feature                  | package.json      | package-lock.json     |
| ------------------------ | ----------------- | --------------------- |
| Created By               | Developer         | npm                   |
| Editable                 | Yes               | Usually No            |
| Stores Dependency Ranges | Yes               | No                    |
| Stores Exact Versions    | No                | Yes                   |
| Stores Dependency Tree   | No                | Yes                   |
| Shared in Git            | Yes               | Yes                   |
| Purpose                  | Project Blueprint | Installation Snapshot |

# Semantic Versioning (SemVer)

Package versions follow Semantic Versioning:

```text
MAJOR.MINOR.PATCH
```

Example:

```text
4.17.21
```

Where:

```text
MAJOR = 4
MINOR = 17
PATCH = 21
```

---

## PATCH Updates

Example:

```text
4.17.20 → 4.17.21
```

Usually contains:

* Bug fixes
* Performance improvements
* Security fixes

Should not break existing code.

---

## MINOR Updates

Example:

```text
4.16.0 → 4.17.0
```

Usually contains:

* New features
* Enhancements

Should remain backward compatible.

---

## MAJOR Updates

Example:

```text
3.0.0 → 4.0.0
```

May contain:

* Breaking changes
* Removed functionality
* API changes

Existing code may stop working.

---

# Version Ranges in package.json

npm allows specifying version ranges rather than exact versions.

This helps receive updates automatically.

---

# Exact Version

Example:

```json
{
  "express": "5.1.0"
}
```

Installs only:

```text
5.1.0
```

No automatic updates.

---

# Tilde (~)

## Definition

Allows PATCH updates only.

Example:

```json
{
  "express": "~5.1.0"
}
```

### Range

```text
>=5.1.0 <5.2.0
```

### Allowed Versions

```text
5.1.0 ✅
5.1.1 ✅
5.1.5 ✅
```

### Not Allowed

```text
5.2.0 ❌
6.0.0 ❌
```

### Memory Trick

```text
~ = Stay in the same MINOR version
```

---

# Caret (^)

## Definition

Allows MINOR and PATCH updates.

Example:

```json
{
  "express": "^5.1.0"
}
```

### Range

```text
>=5.1.0 <6.0.0
```

### Allowed Versions

```text
5.1.1 ✅
5.2.0 ✅
5.5.0 ✅
```

### Not Allowed

```text
6.0.0 ❌
```

### Memory Trick

```text
^ = Stay in the same MAJOR version
```

---

# Comparison of Version Types

| Syntax   | Meaning               |
| -------- | --------------------- |
| `1.2.3`  | Exact Version         |
| `~1.2.3` | Patch Updates Only    |
| `^1.2.3` | Minor + Patch Updates |
| `*`      | Any Version           |

### Visual Example

#### Exact Version

```text
1.2.3
```

Only:

```text
1.2.3 ✅
```

#### Tilde

```text
~1.2.3
```

```text
1.2.3 ✅
1.2.4 ✅
1.2.9 ✅
1.3.0 ❌
```

#### Caret

```text
^1.2.3
```

```text
1.2.3 ✅
1.3.0 ✅
1.8.0 ✅
2.0.0 ❌
```

---

# Why Caret and Tilde Exist

Suppose a security issue is fixed in:

```text
5.1.1
```

If package.json contains:

```json
"express": "5.1.0"
```

You must update manually.

Using:

```json
"express": "^5.1.0"
```

allows npm to install safe updates automatically.

Benefits:

* Bug fixes
* Security updates
* Performance improvements

without major breaking changes.

# Why We Need package.json and package-lock.json

## package.json

Acts as the project's blueprint.

It answers:

* What packages does this project need?
* What commands can I run?
* What version of dependencies are allowed?

## package-lock.json

Acts as an installation snapshot.

It answers:

* Which exact versions were installed?
* Which dependency tree was used?

Together they make projects:

* Shareable
* Reproducible
* Easier to maintain
* Consistent across all machines

---

# Why We Don't Upload node_modules

The `node_modules` folder can become very large.

Examples:

```text
50 MB
100 MB
500 MB
```

or even larger.

Instead of uploading thousands of dependency files, we upload:

```text
package.json
package-lock.json
```

Anyone can recreate dependencies using:

```bash
npm install
```

# Typical Project Workflow

## Create Project

```bash
npm init -y
```

Creates:

```text
package.json
```

---

## Install Dependencies

```bash
npm install express
```

Creates:

```text
package.json
package-lock.json
node_modules/
```

---

## Push to GitHub

Upload:

```text
package.json
package-lock.json
```

Ignore:

```text
node_modules/
```

using `.gitignore`.

---

## Clone Project

```bash
git clone <repository-url>
cd project
npm install
```

npm recreates the entire environment.
