Node.js Package Management Notes
Introduction

When working with Node.js projects, we often install external libraries (called packages) such as Express, React, Mongoose, Lodash, etc.

Managing these packages manually would be difficult, especially in team projects. To solve this problem, npm (Node Package Manager) uses:

package.json
package-lock.json

These files help developers manage dependencies, maintain consistency, and make projects easy to share.

What is a Dependency?

A dependency is a package that your project needs in order to work.

Example:

npm install express

This installs Express and adds it as a dependency.

Without dependencies, we would have to write everything from scratch.

package.json
Definition

package.json is the main configuration file of a Node.js project.

It acts as the blueprint of the project and tells npm:

Which packages are needed
Which versions are acceptable
How to run the project
Project metadata
Example
{
  "name": "my-app",
  "version": "1.0.0",
  "dependencies": {
    "express": "^5.1.0",
    "mongoose": "^8.0.0"
  },
  "scripts": {
    "start": "node server.js"
  }
}
Information Stored in package.json
Project Metadata
{
  "name": "my-app",
  "version": "1.0.0"
}

Contains project information.

Dependencies
{
  "dependencies": {
    "express": "^5.1.0"
  }
}

Lists packages required by the project.

Scripts
{
  "scripts": {
    "start": "node server.js",
    "test": "jest"
  }
}

Allows running commands using npm.

Example:

npm start
npm test
Purpose of package.json

Imagine you build an application and push it to GitHub.

Without package.json, other developers would not know:

Which packages to install
Which versions to use
How to run the project

With package.json, they simply run:

npm install

and npm installs all required dependencies automatically.

package-lock.json
Definition

package-lock.json is automatically generated by npm.

It records the exact versions of every installed package and dependency.

Example

Suppose package.json contains:

{
  "dependencies": {
    "express": "^5.1.0"
  }
}

npm may install:

express@5.2.0

The lock file records:

{
  "packages": {
    "node_modules/express": {
      "version": "5.2.0"
    }
  }
}
Why package-lock.json Exists

Without a lock file:

Developer A installs:

express@5.1.0

Developer B installs:

express@5.2.0

Different versions can cause different behavior and bugs.

With a lock file:

Everyone gets:

express@5.1.0

or whatever version was recorded.

This ensures consistency.

What package-lock.json Stores
Exact Package Versions
express@5.2.0
Full Dependency Tree

Example:

express
├── body-parser
├── cookie
├── debug
└── mime-types

The lock file stores every dependency and sub-dependency.

Purpose of package-lock.json

Provides:

Reproducible builds
Consistent installations
Same environment for all developers
Fewer "works on my machine" issues
Difference Between package.json and package-lock.json
Feature	package.json	package-lock.json
Created By	Developer	npm
Editable	Yes	Usually No
Stores Dependency Ranges	Yes	No
Stores Exact Versions	No	Yes
Stores Dependency Tree	No	Yes
Shared in Git	Yes	Yes
Purpose	Project Blueprint	Exact Installation Snapshot
Semantic Versioning (SemVer)

Package versions follow Semantic Versioning:

MAJOR.MINOR.PATCH

Example:

4.17.21

Where:

MAJOR = 4
MINOR = 17
PATCH = 21
PATCH Updates

Example:

4.17.20 → 4.17.21

Usually contains:

Bug fixes
Performance improvements
Security fixes

Should not break existing code.

MINOR Updates

Example:

4.16.0 → 4.17.0

Usually contains:

New features
Enhancements

Should remain backward compatible.

MAJOR Updates

Example:

3.0.0 → 4.0.0

May contain:

Breaking changes
Removed functionality
API changes

Existing code may stop working.

Version Ranges in package.json

npm allows specifying version ranges rather than exact versions.

This helps receive updates automatically.

Exact Version

Example:

{
  "express": "5.1.0"
}

Only installs:

5.1.0

No automatic updates.

Tilde (~)
Definition

Allows PATCH updates only.

Example:

{
  "express": "~5.1.0"
}
Range
>=5.1.0 <5.2.0
Allowed Versions
5.1.0 ✅
5.1.1 ✅
5.1.5 ✅
Not Allowed
5.2.0 ❌
6.0.0 ❌
Memory Trick
~ = Stay in the same MINOR version
Caret (^)
Definition

Allows MINOR and PATCH updates.

Example:

{
  "express": "^5.1.0"
}
Range
>=5.1.0 <6.0.0
Allowed Versions
5.1.1 ✅
5.2.0 ✅
5.5.0 ✅
Not Allowed
6.0.0 ❌
Memory Trick
^ = Stay in the same MAJOR version
Comparison of Version Types
Exact Version
"express": "5.1.0"

Installs only:

5.1.0
Tilde
"express": "~5.1.0"

Installs:

5.1.x

Only patch updates.

Caret
"express": "^5.1.0"

Installs:

5.x.x

Minor and patch updates.

Why Caret and Tilde Exist

Suppose a security issue is fixed in:

5.1.1

If package.json contains:

"express": "5.1.0"

You must update manually.

Using:

"express": "^5.1.0"

allows npm to install safe updates automatically.

Benefits:

Bug fixes
Security updates
Performance improvements

without major breaking changes.

Why We Don't Upload node_modules

The node_modules folder can be very large.

Example:

50 MB
100 MB
500 MB

or even larger.

Instead of uploading thousands of files, we upload:

package.json
package-lock.json

Anyone can recreate the dependencies using:

npm install
Typical Project Workflow
Create Project
npm init -y

Creates:

package.json
Install Dependencies
npm install express

Creates:

package.json
package-lock.json
node_modules/
Push to GitHub

Upload:

package.json
package-lock.json

Ignore:

node_modules/

using .gitignore.

Clone Project
git clone <repository>
cd project
npm install

npm recreates the entire environment.

Interview Questions
What is package.json?

A configuration file that describes the project, dependencies, scripts, and metadata.

What is package-lock.json?

A file generated by npm that records exact installed package versions and dependency tree.

Why do we need package-lock.json?

To ensure every developer and server installs exactly the same package versions.
